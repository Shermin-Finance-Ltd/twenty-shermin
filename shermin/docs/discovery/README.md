# Discovery — BDM and Sales Support workstream

Prep materials for the Phase 0 discovery interviews on retailer onboarding. Barney runs the interviews, these docs are the brief.

## Files

| File | What it is |
|---|---|
| [current-state.md](current-state.md) | What we already think we know about how onboarding works today, with anything inferred flagged for confirmation. |
| [interview-tony.md](interview-tony.md) | 30-min commercial interview with Tony Lilley, Commercial Director. Pipeline visibility, BDM adoption, KPIs, self-employed vs PAYE. |
| [interview-gemma.md](interview-gemma.md) | 30-min operational interview with Gemma Bloomer, Office Manager. Sales Support workflow, compliance, Setup-in-Stax, exception cases. |
| [interview-bdm.md](interview-bdm.md) | 20-min end-user interview with a sample BDM. Lead intake, info needs, mobile vs desktop. |
| [interview-sales-support.md](interview-sales-support.md) | 30-min power-user interview with a Sales Support team member. Walk-through of a real onboarding, compliance, Setup-in-Stax, checklists vs required fields. |
| [diff-vs-proposed-v1.md](diff-vs-proposed-v1.md) | "If interviews confirm X, the v1 design needs Y." Live amendment list once interviews are run. |

## How to use this folder

1. Read `current-state.md` first so you know what we already think is true.
2. Run the four interviews (Tony, Gemma, BDM, Sales Support) in roughly that order. Tony and Gemma set the frame, the BDM and Sales Support interviews ground-truth it.
3. After each interview, mark up `diff-vs-proposed-v1.md` with what was confirmed, what was wrong, and any new "if X then Y" pairs the conversation surfaced.
4. Once all four are done, write a short closing memo and feed the confirmed deltas back into the v1 data model and stage spec.
